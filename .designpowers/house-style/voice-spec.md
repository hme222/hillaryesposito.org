# Voice Specification

## Register
Sentence length: 3 to 24 words
Contractions: yes
Person: first person for Hillary's contribution; second person only for direct actions
Formality: calm and direct; technical terms are tied to a visible artifact or decision
Humor: dry restraint is allowed in personal context; banned in evidence, limitations, and application actions

## Hard bans
- Generic fit claims without a named project, decision, or result
- Developer-platform, Postgres, infrastructure, production-usage, or shipping claims not supported by source evidence
- `seamless`, `leverage`, `elevate`, `cutting-edge`, `game-changing`, and `unlock`
- Defensive apology language that asks the recruiter to reject the application
- Hidden or ghost text

## Required
- Claims include the project, Hillary's contribution, the observable output, and the current status or limitation when material.
- Buttons name the resulting action or object.
- Research numbers state the method or decision they informed.
- Outcome numbers preserve initiative-level attribution.
- Grove is always a functional prototype in Phase 2 of 3, not a beta or shipped product.

## Paired examples
Button BAD: View a case study
Button GOOD: Review Grove

Empty state BAD: No projects found
Empty state GOOD: This private page recommends Grove, MSK, and Mobbin for the Supabase role.

Error BAD: Something went wrong
Error GOOD: This private page did not load. Return to selected work and use the recruiter contact link.

Headline BAD: Making technical products easier to understand, use, and extend
Headline GOOD: Built a working React prototype. Improved workflows serving 21,000+ staff.

Proof BAD: Strong systems thinker and cross-functional collaborator
Proof GOOD: A workflow map gave clinical, IT, and operations one system failure to resolve together.
