# Laws of UX Selection Guide

Source baseline: Jon Yablonski, [Laws of UX](https://lawsofux.com/). The site is a practitioner resource that makes psychology heuristics accessible to designers. This guide is an attributed practitioner synthesis, not a reproduction of the source and not a substitute for primary research.

## Select by design question

### Choice, attention, and cognitive demand

| Lens | Use it to investigate | Guardrail |
|---|---|---|
| Choice Overload | Whether an option set creates avoidance or weak confidence | Do not hide necessary comparison information |
| Hick's Law | Decision time as options and complexity increase | Complexity matters more than raw option count |
| Cognitive Load | Mental effort created by task and presentation | Reduce extraneous load, not essential meaning |
| Selective Attention | Whether the intended signal can win against competing stimuli | Do not make secondary content invisible |
| Cognitive Bias | Where designer or user judgment may be systematically distorted | Name the specific bias and test it |

### Memory, learning, and mental models

| Lens | Use it to investigate | Guardrail |
|---|---|---|
| Chunking | Whether information forms meaningful, labelled groups | Group by user meaning, not visual convenience |
| Working Memory | Information users must hold while acting | Prefer recognition, context, and persistence |
| Miller's Law | Working-memory pressure | Never enforce 7±2 as a universal item cap |
| Mental Model | Fit between system behavior and user expectation | Research the model; do not assume it |
| Jakob's Law | Value of familiar conventions | Keep task mechanics familiar without erasing brand |
| Paradox of the Active User | Learning by doing rather than reading documentation | Provide contextual guidance and safe exploration |
| Serial Position Effect | Emphasis created by first and last positions | Do not bury critical items in the middle |
| Zeigarnik Effect | How interruption and incompletion affect recall | Support honest resumption; avoid manufactured anxiety |

### Perception, grouping, and hierarchy

| Lens | Use it to investigate | Guardrail |
|---|---|---|
| Aesthetic-Usability Effect | Whether polish improves perceived ease and trust | Perception is not actual usability |
| Law of Common Region | Grouping through shared boundaries | Avoid excessive container noise |
| Law of Proximity | Grouping through spacing | Preserve touch separation and reading order |
| Law of Prägnanz | Whether forms and structure resolve clearly | Simplicity must not erase needed nuance |
| Law of Similarity | Whether shared appearance communicates shared behavior | Distinguish different actions clearly |
| Law of Uniform Connectedness | Whether explicit visual connection clarifies relationship | Do not create false relationships |
| Von Restorff Effect | Whether a distinct item receives appropriate attention | Reserve distinctiveness for real priority |

### Interaction, performance, and input

| Lens | Use it to investigate | Guardrail |
|---|---|---|
| Fitts's Law | Target size, distance, reach, and acquisition effort | Test real devices, inputs, and motor needs |
| Doherty Threshold | Whether response timing preserves interaction momentum | Give honest feedback; never fake completion |
| Postel's Law | Tolerance of humane input variation | Security and data integrity still require strict boundaries |

### Progress, motivation, and experience memory

| Lens | Use it to investigate | Guardrail |
|---|---|---|
| Flow | Balance among challenge, skill, feedback, and interruption | Do not optimize engagement against user wellbeing |
| Goal-Gradient Effect | Whether visible progress supports completion | Progress must be accurate |
| Peak-End Rule | Which high point and ending shape remembered experience | Repair failures throughout, not only the ending |

### Complexity, prioritization, and scope

| Lens | Use it to investigate | Guardrail |
|---|---|---|
| Tesler's Law | Where irreducible complexity should live | Move complexity to the system when it can handle it safely |
| Occam's Razor | Whether a simpler adequate solution exists | Simple is not the same as sparse |
| Pareto Principle | Which small set of tasks drives most value | Verify product-specific usage rather than assuming 80/20 |
| Parkinson's Law | Whether open-ended time or workflow expands effort | Do not create unsafe or inaccessible time pressure |

## Conflict priority

Resolve conflicts in this order:

1. accessibility, safety, and informed consent;
2. task success and error recovery;
3. user control and comprehension;
4. evidence from representative users;
5. established conventions and design-system consistency;
6. efficiency, aesthetics, persuasion, and novelty.

## Evidence labels

- **Verified:** the source or actual interface evidence was inspected.
- **Index-only:** only a title or pointer is known; do not attribute recommendations.
- **Practitioner synthesis:** a contextual application constructed from verified principles.
- **Proposed:** the design prediction has not yet been validated.
